# Polaris – Project Overview

## Vision

Polaris is the single source of truth for all current and planned ports within the ASTRONOMA-GROUP ecosystem. It provides a unified, authoritative reference that keeps every team member aligned on project scope, status, and direction.

## Goals

- **Centralization** – Consolidate all port-related documentation, decisions, and status updates into one repository.
- **Transparency** – Provide clear visibility into what is built, what is planned, and what has changed.
- **Consistency** – Establish shared standards so every port is documented, tracked, and delivered the same way.
- **Discoverability** – Make it easy for contributors and stakeholders to find what they need quickly.

## Scope

Polaris covers:

- Catalog of all active and planned ports (see [`ports.md`](ports.md))
- Architecture and component relationships (see [`architecture.md`](architecture.md))
- Onboarding and contribution processes (see [`getting-started.md`](getting-started.md) and [`contributing.md`](contributing.md))
- A running changelog of significant changes (see [`changelog.md`](changelog.md))

## Non-Goals

- Polaris does not contain source code for individual ports. Each port lives in its own repository and is referenced here.
- Polaris is not a runtime system; it is a documentation and coordination layer.

## Stakeholders

| Role | Responsibility |
|------|----------------|
| Project Leads | Define scope, approve ports, review architecture decisions |
| Contributors | Propose and implement ports, keep documentation current |
| Reviewers | Validate documentation and port status before merge |
